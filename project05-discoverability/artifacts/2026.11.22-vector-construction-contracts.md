## Manual cases and contrary controls

These are source-derived cases, not executed behavior:

1. **Zero-size cold build:** supply valid path/provider and batch size0; allow discovery/extraction to complete. The phase2 call invokes `chunks(0)`, including with no documents. The Rust API precondition predicts a panic. This prediction is limited to that reached branch.
2. **Earlier exits:** omit path or provider and the builder returns `Err`; a discovery error or configured fail-fast extraction error can also stop before batching. These cases do not reach `chunks`.
3. **Cache-hit control:** with a fresh content hash and loadable cache, build returns before batching; zero alone does not imply the cache-hit call reaches the panic. A cache miss or `skip_cache` restores the cold path.
4. **Positive batch control:** default64 and the in-file positive batch-size2 example exercise ordinary nonzero sizes in source tests; their presence does not validate zero handling.
5. **Append provider control:** the documented append example intentionally shares the same provider instance across initial build and append. It is evidence for a same-provider intended use, not proof that different spaces are rejected or supported.
6. **Cache controls:** existing source cases cover same-provider, unchanged-content hit; changed-content miss; and `skip_cache` rebuild. They do not vary provider/model while holding content constant.
7. **Shape controls:** the mock accepts8 and16 dimensions. A different dimension is not evidence of a different semantic space; the source-level cosine branch maps vector-length mismatch to0. No vectors were made here.
8. **Cardinality control:** default and mock batch implementations produce one result per input by construction. A short/long custom result remains a defensive-contract question, not a current built-in failure.

### Questions kept open

- Is `build_append` contractually restricted to the backend's current embedding space? If yes, which stable identity can the API compare, given `name()` is diagnostic and dimensions are insufficient?
- Must callers use distinct cache paths per provider/model/version, or should cache contents record an embedding identity and reject a mismatch? The inspected cache API specifies content freshness but not this partition rule.
- Should custom providers be required to return exactly one vector per input, and should the builder return an error when cardinality differs?
- Should zero batch size be rejected when configured or returned as a build error? This review identifies the panic path but chooses no compatibility/API shape.
