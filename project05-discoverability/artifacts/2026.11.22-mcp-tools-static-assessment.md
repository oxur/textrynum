## Architecture and contract map

- `fabryk-mcp-content` exports filesystem content/guide/question/source providers, provider traits and `ContentTools`, `SourceTools`, `GuideTools` and `QuestionSearchTools` (`crates/fabryk-mcp-content/src/lib.rs:32–58`). Provider summaries and response structs are serialized independently of configurable MCP names (`src/fs_content_provider.rs:41–93`; `src/tools.rs:125–225,228–355`).
- Content list requests extract `category` and `limit`, then send remaining JSON properties to `list_items_filtered` (`src/tools.rs:307–332`). The public trait's default implementation ignores those extra properties (`src/traits.rs:114–127`); an implementation must opt into filtering. `with_extra_list_schema` only adds visible schema properties (`src/tools.rs:180–190,247–256`).
- Filesystem providers establish their own data contracts: content title/category fallbacks and metadata projection (`fs_content_provider.rs:122–161`), guide frontmatter/heading/stem and description/paragraph fallback (`fs_guide_provider.rs:86–120`), question similarity/boost/threshold/order/limit (`fs_question_provider.rs:59–79,128–164`), and converted versus registered source behavior (`fs_source_provider.rs:190–320`).
- Content tool names come from slot plus optional prefix or a slot override (`src/tools.rs:157–218,258–305`); provider type names only customize descriptions (`:230–303`). The get description separately reconstructs the list name from `content_type_name_plural` (`:267–290`), which is not necessarily the configured tool name.
- FTS declares `search` and `search_status`; its README currently says `search_items`. Search extracts its known filters and forwards other properties as FTS `extra_filters` (`crates/fabryk-mcp-fts/src/tools.rs:112–116,191–245,248–303`). Its MCP response intentionally retains ID, title, description, category, source, snippet, relevance and content type, not optional path/chapter/section (`:41–75,305–328`; underlying fields at `fabryk-fts/src/backend.rs:73–115`). Existing FA-RS-035 owns the FTS/graph README default-name mismatch; it is not duplicated here.
- Graph exposes 17 registered tools (`crates/fabryk-mcp-graph/src/tools.rs:184–220,360–658`) and a configurable node filter whose stated contract is post-processing selected node-list results (`:312–320`). Each handler's actual path is recorded in the matrix. `graph_learning_path` filters steps and updates count but leaves each original one-based step number untouched (`:1001–1021`; result fields `fabryk-graph/src/algorithms.rs:90–113,565–601`).
- Semantic search exposes keyword/vector/hybrid mode and category/source/limit fields (`crates/fabryk-mcp-semantic/src/tools.rs:23–36,211–247`). Keyword forwards category and source; vector builds only query+limit; hybrid filters FTS but not vector before RRF (`:262–328`). The companion `VectorSearchParams` has category and metadata-filter fields/builders (`fabryk-vector/src/types.rs:185–240`), so category omission is directly established. No source-to-vector metadata mapping is established in this intake, so source behavior remains a question.
- The umbrella crate re-exports component crates and separates its historical `0.2` snippets from the current unreleased `0.5.0` SDK explanation (`crates/fabryk-mcp/Cargo.toml:13–25`; `README.md:43–68`; `src/lib.rs:6–15`). Five how-tos were checked against the assigned current source rows; the full text is represented in the 31-row matrix. Earlier FA-RS-036/037/055 statuses remain distinct and unchanged.

## Proposed findings and owner questions

The cumulative report proposes four new roots, FA-RS-057–060. All are static proposals for CDC review. No implementation repair is authorized by this assessment. Four questions remain ungraded because the exact policy or a transport boundary is not established by these source rows. See the cumulative report for each source, severity rationale, consumer, owner, compatibility direction, oracle and scale limits.

- **FA-RS-057 — semantic vector and hybrid searches drop category filtering.** The public MCP input advertises category for every mode, but only the FTS leg receives it.
- **FA-RS-058 — generated content get guidance can name a nonexistent list tool.** Provider plural and configured tool prefix/slot are independent settings.
- **FA-RS-059 — category title casing can panic on a multibyte first character.** Frontmatter and directory-derived category values are strings without a corresponding ASCII restriction in this provider.
- **FA-RS-060 — guide description fallback parses the complete document input.** With guide frontmatter lacking `description`, the fallback is given the complete source text; the parser does not explicitly remove frontmatter. Keep the body-only intent and exact parser result visible for independent review.
- **Q06-01 — Does the MCP dispatch boundary reject an out-of-enum semantic mode before this handler?** The schema has an enum, but the handler's catch-all branch selects hybrid. Owner: MCP transport/registry contract owner. Future oracle: submit an unknown mode through the supported dispatch boundary and establish whether it is rejected or routed.
- **Q06-02 — How should `source` map to vector document metadata?** Semantic inputs advertise source, FTS consumes it, but vector parameters expose category and arbitrary metadata filters rather than a named source field. Owner: semantic/vector integration owner. Future oracle: define indexed source metadata and show mode-specific filtering with matching and nonmatching documents.
- **Q06-03 — Should filtered learning-path steps be renumbered or preserve original path ordinals?** Filtering retains original `step` values while `total_steps` becomes the emitted count. Owner: graph/MCP contract owner. Future oracle: a three-step path filtered to omit its middle step, then a stated rule for displayed ordinals and total.
- **Q06-04 — Are the health how-to state tables intended to be exhaustive?** `ServiceState` exposes `Stopped`, `Starting`, `Ready`, `Degraded`, `Stopping`, and `Failed` (`fabryk-core/src/service.rs:152–195`); `health_router` returns 200 for `Ready`/`Stopped` and 503 for other states (`fabryk-mcp-core/src/health_router.rs:61–105`), while the how-to tables cover a subset (`docs/howtos/mcp-health.md:154–202`; startup state narrative at `docs/howtos/mcp-async-startup.md:17–53,165–208,288–331`). The listed outcomes may be correct without being exhaustive. Owner: MCP health/startup documentation and lifecycle API owners. Future oracle: state whether the tables are illustrative or complete, and if complete enumerate all six states with their health mapping. No runtime route check or severity grade.

No conclusion is drawn about external client schema validation, user task success or number of MCP calls.

## Contrary controls and valid boundaries

2. The semantic limit remains capped at 50 and is forwarded as the per-backend limit; no limit defect is proposed (`fabryk-mcp-semantic/src/tools.rs:262–264,273–276,281–286,296–314`).
3. `ContentTools` correctly dispatches the configured name and custom get-ID field; the mismatch is generated explanatory text under independent prefix/plural settings, not call dispatch (`fabryk-mcp-content/src/tools.rs:209–218,307–342`; tests `:1038–1055,1660–1728`).
4. Content title fallback and category fallback are tested for ordinary ASCII/body cases; none of those tests establishes the multibyte category path (`fs_content_provider.rs:568–628`; category display `:231–258`).
5. Guide description tests cover frontmatter with a description and plain Markdown body fallback separately, but not frontmatter without description (`fs_guide_provider.rs:316–345`). Guide title frontmatter/heading/stem controls are present (`:282–313`).
6. Graph related filtering occurs before its limit, and centrality filters before `take(limit)`; those remain positive controls against a general “post-filter breaks limits” claim (`fabryk-mcp-graph/src/tools.rs:664–694,823–851`). Bridge algorithms apply their own maximum before MCP post-filtering, which can yield fewer items but still respects an upper bound (`:853–869,1024–1047`).

8. Source-provider tests cover converted/unconverted listing, section reads, missing-source errors and source-path lookup; no filesystem/provider operation ran in this assessment (`fabryk-mcp-content/src/fs_source_provider.rs:372–567`).
9. FTS passes unknown request fields into `extra_filters`, but the default FTS API does not promise every backend implements every extra key; no arbitrary-filter completeness claim is made (`fabryk-mcp-fts/src/tools.rs:258–303`; `fabryk-fts/src/backend.rs:67–70`).
