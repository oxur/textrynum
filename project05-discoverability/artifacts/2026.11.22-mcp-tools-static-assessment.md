## Architecture and current contract map

- `ContentTools` defaults to `list`, `get`, and `categories`; prefixes and per-slot names alter registrations (`crates/fabryk-mcp-content/src/tools.rs:125–218,258–305`). The get input field is independently configurable, but that does not rename the provider's returned `id` (`:193–207,267–290,335–340`; filesystem summary `fs_content_provider.rs:147–160`). `SourceTools` has five separately named source slots (`tools.rs:395–404`).
- Content providers use frontmatter and fallback paths for summaries, retrieval, guide titles/descriptions, questions, and sources. In particular, category strings can come from frontmatter or parent directories (`fs_content_provider.rs:130–160`), and the category list performs a byte slice after reading a Unicode scalar (`:231–258`). Guide description fallback receives the full document, but the exact helper output for frontmatter without an explicit description is not established by the assigned source alone (`fs_guide_provider.rs:106–120,134–159`; `fabryk-content/src/markdown/parser.rs:109–150`).
- Semantic input schema advertises category and source without mode restrictions (`crates/fabryk-mcp-semantic/src/tools.rs:227–243`). Keyword forwards both to FTS; vector forwards neither; hybrid forwards both to its FTS leg but neither to the vector leg (`:265–328`). `VectorSearchParams` exposes category and arbitrary metadata filters, not a named source parameter (`crates/fabryk-vector/src/types.rs:185–240`). The source-to-vector mapping remains a design question, separate from the current unqualified source-filter promise.
- Semantic result bounds differ by branch. Keyword/vector use the clamped limit; hybrid requests twice that limit from each backend, then RRF returns the requested limit when a vector backend exists. If no vector backend is available, the handler serializes the FTS result directly without a final trim (`fabryk-mcp-semantic/src/tools.rs:262–328`). This is a concrete bounded maximum violation, conditional on an FTS backend returning the requested number of eligible hits.
- Graph filter application is per result shape, not uniform. `graph_related` filters its node list before truncating; neighborhood filters nodes but retains the original edge list; bridge handlers filter an already bounded candidate list; learning path filters steps and updates `total_steps` without renumbering retained ordinals (`crates/fabryk-mcp-graph/src/tools.rs:312–320,664–694,765–803,853–869,1001–1047`; graph step contract `fabryk-graph/src/algorithms.rs:90–113,565–601`).
- The exact current public doc examples were compared with declared types, names, and route mounting. The current `FilterSummary` fields differ from the first example; a hyphenated server name is retained literally in both directory tool name and result key; direct HTTP serving mounts `/mcp`; and the health guide's auth import differs from the current package/facade (`fabryk-mcp-core/src/discoverable.rs:138–155,302–305,352–355,547,598–604`; `fabryk-mcp-core/src/server.rs:263–276`; `fabryk-mcp/Cargo.toml:13–19`, `src/lib.rs:9–15`; `fabryk-mcp-auth/Cargo.toml:1–9`).
